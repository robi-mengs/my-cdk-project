# TES-DEV CDK sample: a notes API

A small AWS CDK app in Python that you can deploy from your laptop and then from GitHub Actions using OIDC. It goes with the PDF guide *Deploying to AWS from GitHub Actions*.

```
  curl / browser
        |
        v
  API Gateway (HTTP API)      public URL, throttled to 10 requests/second
        |
        v
  Lambda (Python 3.13)        lambda/handler.py
        |
        v
  DynamoDB table              on-demand, pay per request
```

It costs nothing while idle, and `cdk destroy` removes all of it.

## What is in here

| Path | What it is |
|---|---|
| `app.py` | Entry point. Pins the account and region, and names the stack after you. |
| `tes_dev_cdk_sample/tes_dev_cdk_sample_stack.py` | The infrastructure: table, function, log group, API. |
| `lambda/handler.py` | The code that runs in Lambda. |
| `tests/unit/` | Tests for the infrastructure and for the Lambda code. |
| `.github/workflows/ci.yml` | Runs the tests and `cdk synth` on every pull request. Needs no AWS access. |
| `.github/workflows/deploy.yml` | Deploys to AWS on every push to `main`, using OIDC. |
| `cdk.json` | Tells the CDK CLI how to run the app. Generated by `cdk init`. |

## Before you start

- Python 3.13 (3.10 or newer works)
- Node.js 22 or newer
- AWS CLI v2, with your SSO profile set up
- The CDK CLI: `npm install -g aws-cdk`

Every command below uses `--profile YOUR_PROFILE`. Replace it with your own profile name.

## 1. Set up the project

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate.bat
pip install -r requirements.txt -r requirements-dev.txt
pytest
```

All tests should pass. None of them touch AWS.

## 2. Pick your owner name

You all share one AWS account. If two people deployed a stack with the same name, the second would overwrite the first. So every stack is named after its owner:

```bash
cdk synth -c owner=robiel          # creates the stack NotesSample-robiel
```

Use lowercase letters, digits and dashes. If you forget `-c owner=...`, CDK stops and tells you.

To avoid typing it every time, add it to the `"context"` block in `cdk.json`:

```json
"context": {
  "owner": "robiel",
  ...
}
```

## 3. Log in and bootstrap (once per account, one person only)

```bash
aws sso login --profile YOUR_PROFILE
aws sts get-caller-identity --profile YOUR_PROFILE    # should show account 785269092218
```

CDK needs a one-time setup in the account called *bootstrapping*. It creates a stack named `CDKToolkit`. **There is only one per account, and you all share it.** Check whether someone has already done it:

```bash
aws cloudformation describe-stacks --stack-name CDKToolkit \
  --query "Stacks[0].StackStatus" --region us-east-1 --profile YOUR_PROFILE
```

- `CREATE_COMPLETE` or `UPDATE_COMPLETE`: it is done. Skip to step 4.
- `Stack with id CDKToolkit does not exist`: agree who does it, then that person runs:

```bash
cdk bootstrap aws://785269092218/us-east-1 --profile YOUR_PROFILE
```

- `ROLLBACK_COMPLETE`: a previous attempt failed. See [Troubleshooting](#troubleshooting).

## 4. Deploy from your laptop

```bash
cdk diff   -c owner=robiel --profile YOUR_PROFILE    # see what will be created
cdk deploy -c owner=robiel --profile YOUR_PROFILE
```

CDK shows the IAM changes and asks you to confirm. When it finishes it prints the outputs:

```
Outputs:
NotesSample-robiel.ApiUrl = https://abc123.execute-api.us-east-1.amazonaws.com
NotesSample-robiel.TableName = NotesSample-robiel-NotesTable...
```

## 5. Try it

```bash
API=https://abc123.execute-api.us-east-1.amazonaws.com    # your ApiUrl

# create a note
curl -s -X POST "$API/notes" -H "content-type: application/json" -d '{"text": "hello from TES-DEV"}'

# list notes
curl -s "$API/notes"

# get one (use an id from the list)
curl -s "$API/notes/PUT-AN-ID-HERE"

# delete it
curl -s -X DELETE "$API/notes/PUT-AN-ID-HERE" -o /dev/null -w "%{http_code}\n"    # prints 204
```

Then look around the console: the table in DynamoDB, the function in Lambda, and its logs in CloudWatch under **Log groups**.

## 6. Deploy from GitHub Actions

The PDF guide covers each step in detail. The short version:

**a. Push this folder to your own GitHub repository.**

```bash
git init -b main
git add .
git commit -m "Notes sample"
git remote add origin https://github.com/YOUR_USER/YOUR_REPO.git
git push -u origin main
```

The first push runs the Deploy workflow, which fails because nothing is configured yet. That is expected.

**b. Make sure the GitHub OIDC provider exists.** There is one per account. If a teammate made it, skip this.

```bash
aws iam list-open-id-connect-providers --profile YOUR_PROFILE
```

**c. Create a role that only your repository can assume.** Repositories created on or after 15 July 2026 use GitHub's new *immutable* subject format, which includes two numeric IDs:

```bash
gh api /users/YOUR_USER --jq .id              # OWNER_ID
gh api /repos/YOUR_USER/YOUR_REPO --jq .id    # REPO_ID
```

Save this as `trust.json`, filling in your names and both IDs:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {
      "Federated": "arn:aws:iam::785269092218:oidc-provider/token.actions.githubusercontent.com"
    },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {
        "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
        "token.actions.githubusercontent.com:sub": "repo:YOUR_USER@OWNER_ID/YOUR_REPO@REPO_ID:ref:refs/heads/main"
      }
    }
  }]
}
```

```bash
aws iam create-role --role-name NotesSampleDeployRole-robiel \
  --assume-role-policy-document file://trust.json --profile YOUR_PROFILE

# CDK deploys through its own bootstrap roles, so this is all the role needs
aws iam put-role-policy --role-name NotesSampleDeployRole-robiel --policy-name CdkDeploy \
  --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"sts:AssumeRole","Resource":"arn:aws:iam::785269092218:role/cdk-*"}]}' \
  --profile YOUR_PROFILE
```

**d. Tell the workflow which role and owner to use.** In your repository go to **Settings > Secrets and variables > Actions > Variables** and add:

| Name | Value |
|---|---|
| `AWS_ROLE_ARN` | `arn:aws:iam::785269092218:role/NotesSampleDeployRole-robiel` |
| `OWNER` | `robiel` (same as on your laptop, so it updates the same stack) |

These are *variables*, not secrets. Neither value is sensitive; OIDC means there is no key to protect.

**e. Run it.** Go to **Actions > Deploy > Run workflow**, or push any change to `main`. The "Confirm who we are" step should print an assumed-role ARN containing `NotesSampleDeployRole-robiel`. If it gets that far, OIDC is working.

## 7. Clean up

```bash
cdk destroy -c owner=robiel --profile YOUR_PROFILE
```

This deletes the table (and its data), the function, the logs and the API. Leave `CDKToolkit` in place; the others need it.

## Cost

- **Idle:** effectively $0. Nothing here charges by the hour.
- **Using it:** fractions of a cent per thousand requests.
- The account has a **$20 monthly budget**. At 90% your access is restricted and at 100% it is cut off, automatically. That stops new actions, not resources already running, so delete what you are not using.

## Troubleshooting

| You see | It means |
|---|---|
| `Tell CDK whose stack this is` | Add `-c owner=yourname`. |
| `This stack uses assets, so the toolkit stack must be deployed` or `SSM parameter /cdk-bootstrap/hnb659fds/version not found` | The account is not bootstrapped. Step 3. |
| `CDKToolkit` is `ROLLBACK_COMPLETE`, or `bucket cdk-hnb659fds-assets-... already exists` | A bootstrap failed. Delete both, then bootstrap again: `aws cloudformation delete-stack --stack-name CDKToolkit --region us-east-1 --profile YOUR_PROFILE`, wait for it, then `aws s3 rb s3://cdk-hnb659fds-assets-785269092218-us-east-1 --force --profile YOUR_PROFILE` |
| `The security token included in the request is expired` | Your SSO session ended. `aws sso login --profile YOUR_PROFILE`. |
| GitHub: `Not authorized to perform sts:AssumeRoleWithWebIdentity` | The `sub` in `trust.json` does not match your repo. Usually the old vs immutable format; the Actions log shows the exact `sub` it sent. |
| GitHub: `Credentials could not be loaded` | `id-token: write` is missing from the workflow permissions. |
| GitHub: `Set AWS_ROLE_ARN and OWNER` | Step 6d. |
| Anything denied outside us-east-1 | Only us-east-1 is allowed in this account. |
